# 題目一方法總結（Methods Summary）

## 1. 方法亮點（Differentiators）

本專案的核心不是單純「問答」，而是「可驗證、可拒答、可迭代」的年報 RAG 管線：

- `evidence-constrained answering`
  - 回答必須受檢索證據約束，並附來源頁碼。
  - 目標是降低「看起來合理但實際無證據」的回答。
- `refusal-first strategy`
  - 若證據不足、主體不符、或題型不適合推論（例如未來預測），優先拒答。
  - 透過拒答機制把錯誤成本控制在可管理範圍。
- `evaluation pipeline with feedback loop`
  - 以 Excel 問答集批次評估 Accuracy。
  - 進一步做錯誤分類與代表案例回看，形成可持續優化閉環。

## 2. 前處理與 Chunking 的意義

年報內容具表格、重複頁首頁尾、長段落混合敘述等特性，若不前處理會直接影響檢索品質。

### 2.1 前處理重點

- 逐頁抽取文字並保留 page number
- 清理連續空白、異常換行、常見頁首頁尾噪訊
- 統一文字表示（有助後續匹配與評估）

### 2.2 Chunking 設計重點

- 避免切太碎（保留語意完整度）
- 保留 overlap（降低關鍵句被切斷風險）
- 每個 chunk 都包含 `chunk_id/page/text/source`

### 2.3 對成效的實務影響

- 提升召回穩定度，減少答非所問
- 降低數字題誤答（例如比率、金額、年度比較）
- 讓頁碼引用更可信、可回查

## 3. 錯誤分析如何回饋到系統優化

本專案把錯誤分析當成優化控制台，而不是只看單一 Accuracy。

### 3.1 錯誤類型

- `retrieval_error`：找不到關鍵證據或召回不足
- `synthesis_error`：有證據但整合回答偏離題意
- `numeric_error`：數值/單位/比率處理不一致
- `multi_question_error`：複合題拆解或覆蓋不足
- `hallucination`：回答內容無法被證據支持
- `formatting_difference`：僅格式差異，不屬於實質錯誤

### 3.2 優化閉環

1. 批次評估產生 `predictions.csv`
2. 錯誤分類產生 `error_analysis.md`
3. 回看代表案例並定位問題來源（檢索/回答/規則）
4. 修正後再次全流程重跑並記錄歷程

這樣的流程能讓每次調整都有依據，避免「改了很多但不確定是否真的變好」。

## 4. 題目一要求對照（報告可直接引用）

- `RAG 系統`：已完成（先檢索、再作答，B 方案）
- `Accuracy 評估`：已完成（批次評估）
- `Hallucination 檢測`：已完成（true hallucination 與 formatting 差異分離）
- `差異化方法`：evidence-constrained + refusal-first + 評估回饋閉環
- `成效提升 insight`：前處理與 chunking 直接影響召回與數值題穩定度

## 5. 金融業落地應用價值

以下場景可直接延伸本專案做 PoC 或內部工具：

### 5.1 研究/IR 場景

- 快速回覆年報、法說資料中的事實查詢
- 附頁碼與可追溯證據，降低資訊誤引

### 5.2 客服與知識庫場景

- 將年報、商品說明、常見問答整合成可引用式問答
- 遇到證據不足時拒答並導引人工處理，降低誤導風險

### 5.3 法遵與稽核場景

- 對關鍵揭露項目做快速檢索與比對（例如治理、風險、永續指標）
- 可追蹤回答來源頁碼，便於稽核與留痕

### 5.4 投資分析支援

- 對跨年度數字與策略敘述做快速彙整
- 透過結構化輸出降低人工整理成本

## 6. 建議後續強化方向

- 擴充「未知題型」測試集，驗證泛化能力
- 引入 hybrid retrieval / reranker，提升複合題召回
- 增加人工 spot-check 流程，作為高風險答案的最後閘門
- 服務化部署（API + 監控 + 權限控管）以支援內部正式應用
