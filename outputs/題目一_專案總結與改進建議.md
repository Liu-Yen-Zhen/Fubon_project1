# 題目一專案總結與改進建議（富邦金控年報 RAG）

## 1. 題目一需求對照

根據題目一要求（年報查詢、Accuracy、幻覺檢測），目前專案對照如下：

- 年報問答系統：已完成（RAG，先檢索再作答，B 方案）。
- 使用資料：`113年報.pdf`、`題目一_附件_問答集.xlsx`、`題目一_補充說明.pdf`。
- 成效驗證：已完成批次評估，輸出 `predictions.csv` 並計算 Accuracy。
- 幻覺檢測：已完成規則式初判，並輸出錯誤分析報告。
- 來源頁碼：回答已附頁碼（pages）。
- 迭代紀錄：已完成逐輪紀錄（run log + progress history + snapshot）。

## 2. 專案 0 -> 1 建置過程

### 階段 A：系統骨架建立

- 建立模組化架構：`ingest/build_index/retrieve/answer/evaluate/error_analysis/progress_report`。
- 設定集中管理：`config.py` + `.env`。
- 一鍵執行流程：`scripts/run_and_record.sh`。

### 階段 B：資料處理與索引

- PDF 逐頁抽字並保留頁碼。
- 文字清理（換行、空白、常見頁首頁尾噪訊）。
- chunking（避免切太碎）。
- 以 OpenAI Embedding 產生向量，建立本地 FAISS 索引。
- 產出索引與 metadata：`faiss.index`、`metadata.jsonl`、`index_manifest.json`。

### 階段 C：檢索與問答

- `retrieve.py`：向量檢索 + 分數門檻 + 詞面補強 + 去重。
- `answer.py`：先檢索，再決定回答或拒答；證據不足不呼叫 LLM。
- Prompt 約束：只允許根據檢索內容回答，強制 JSON 輸出。

### 階段 D：評估與錯誤迭代

- `evaluate.py`：批次讀 Excel（自動辨識欄位）逐題評估 Accuracy。
- `error_analysis.py`：錯誤分類（retrieval/synthesis/numeric/multi-question/hallucination/refusal）。
- `progress_report.py`：整合每輪指標，形成可追蹤優化歷程。

### 階段 E：精修與穩定化

- 修正索引路徑一致性（改為專案根目錄相對路徑邏輯）。
- 加入檢索補強與高頻題型規則抽取（降低漂移）。
- 調整 hallucination 規則，減少「計算題衍生數字」誤判。

## 3. 目前應用技術（重點）

- LLM 與 API：OpenAI Responses API（回答生成）。
- Embedding：OpenAI Embeddings API。
- 向量資料庫：FAISS（本地索引）。
- 檢索策略：向量檢索 + lexical rerank + fallback。
- 拒答機制：檢索不足 / 主體不符 / 預測型問題保守拒答。
- 評估：批次 Accuracy + 規則式幻覺偵測 + 錯誤分類。
- 工程化：模組化、CLI、logging、型別註記、pytest、run history snapshot。

## 5. 不足與風險（建議誠實揭露）

### (1) 可能對附件題庫過度貼合

- 部分規則針對高頻題型做了強化，對附件題庫效果好，但未必等於對未知題同樣穩定。

### (2) 幻覺判定仍屬規則式

- 目前是第一版規則判定，對語義層次不一致（非數字型偏差）仍可能有漏判。

### (3) 評估指標偏單一

- 目前以 Accuracy 為主，尚未加入語義等價評分、人工審核抽查、信心校準指標。

### (4) 上線治理尚未完整

- 尚缺成本監控、延遲監控、異常告警、權限/稽核紀錄等生產級治理能力。

## 6. 下一步修正優先順序（建議）

### P0（先做）

- 建立「未知題」測試集（同義改寫、跨段落整合題、陷阱題），驗證泛化能力。
- 把規則化邏輯與通用邏輯分層，避免持續耦合題庫特徵。

### P1

- 導入混合檢索（BM25 + Vector）與 re-ranker（cross-encoder）提升召回與排序品質。
- 做拒答閾值校準（降低誤拒答與誤作答）。

### P2

- 增加進階評估：語義比對、數值容錯、人工 spot-check 流程。
- 幻覺檢測升級成「規則 + 二次模型驗證」雙軌。

### P3（加分型）

- 加入應用落地：API 服務化 + 問答介面 + 觀測儀表板。
- 以金融情境延伸（法遵查核、風險揭露比對、ESG 指標追蹤）。
